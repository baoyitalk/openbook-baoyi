

**核心矛盾：JavaScript 是单线程的**

```
只有一条路，同一时间只能干一件事
```

**问题来了：**

```javascript
// 假设请求要 3 秒
const data = fetch('/api')  // 如果在这等 3 秒
console.log('hello')         // 页面就卡死 3 秒
```

用户点按钮没反应、动画卡住、整个页面冻结 —— 不能接受。

**解决思路：**

```
不等了，你慢慢请求，好了叫我
我先干别的去
```

**怎么"叫我"？—— 回调函数**

```javascript
// 我先把"要做的事"告诉你
fetch('/api', function 好了叫我() {
  console.log('数据到了')
})

// 然后我继续干别的
console.log('我先走了')
```

**本质就是：**

```
同步 = 我在这等你
异步 = 你好了叫我（回调就是"叫我"的方式）
```

**一句话总结：**

> 单线程不能阻塞 → 需要异步 → 异步需要通知机制 → 回调就是最原始的通知机制

后来的 Promise、async/await 只是让这个"通知"写起来更优雅，本质没变。
