# JavaScript 数据类型 —— 第一性原理拆解

> **核心奥义一句话**：JavaScript 的一切数据行为，都源于「栈存值/地址，堆存对象」这一内存模型的必然推演。

---

## 🎯 第一性原理：从「内存」出发

JavaScript 的数据类型设计，本质上是在回答一个问题：

> **数据在内存中怎么存储和访问？**

理解了这一点，所有的「特性」都会变成「必然」。

---

## 一、最底层的划分：两种存储方式

### 📊 内存模型可视化

```
┌─────────────────────────────────────────────────────────────────┐
│                         计算机内存                               │
├────────────────────────────┬────────────────────────────────────┤
│         栈 Stack           │             堆 Heap                │
│      (小、快、固定)          │         (大、灵活、动态)            │
├────────────────────────────┼────────────────────────────────────┤
│                            │                                    │
│   ┌──────────────────┐     │     ┌──────────────────────┐       │
│   │   age = 25       │     │     │  { name: "John",     │       │
│   ├──────────────────┤     │     │    age: 25,          │       │
│   │   name = 0x001   │─────┼────▶│    hobbies: [...] }  │       │
│   ├──────────────────┤     │     └──────────────────────┘       │
│   │   isActive = true│     │                                    │
│   └──────────────────┘     │     ┌──────────────────────┐       │
│                            │     │  [1, 2, 3, 4, 5]     │       │
│   原始类型：直接存值        │     └──────────────────────┘       │
│   引用类型：存地址(指针)    │     引用类型：实际数据              │
│                            │                                    │
└────────────────────────────┴────────────────────────────────────┘
```

### 🤔 为什么这样设计？

| 数据特点 | 存储位置 | 原因 |
|---------|---------|------|
| 体积小、固定（数字、布尔） | 栈 | 分配回收快，直接操作效率高 |
| 体积大、可变（对象、数组） | 堆 | 灵活扩展，栈里只存指针 |

## 二、8 种数据类型的本质

### 原始类型（7种）— 值本身存在栈里

```
┌─────────────────────────────────────────────────────────────┐
│                     原始类型 (Primitive)                     │
├──────────┬──────────┬──────────┬──────────┬────────────────┤
│  number  │  string  │ boolean  │   null   │   undefined    │
├──────────┴──────────┴──────────┴──────────┴────────────────┤
│              symbol              │         bigint           │
└──────────────────────────────────┴─────────────────────────┘
```

| 类型 | 本质 | 为什么需要它 | 关键细节 |
|------|------|-------------|---------|
| `number` | 64位浮点数 (IEEE 754) | 表示数量 | 整数精度: ±(2⁵³-1)，超过会丢失 |
| `string` | 字符序列 | 表示文本 | 无 char 类型，`"a"` 也是字符串 |
| `boolean` | 1位标志 | 表示逻辑真假 | 只有 `true` / `false` |
| `undefined` | 空位标记 | "声明了但没赋值" | 系统级的"空" |
| `null` | 空值标记 | "故意设为空" | 开发者主动设置的"空" |
| `symbol` | 唯一标识符 | 防止属性名冲突 | ES6 新增 |
| `bigint` | 任意精度整数 | 突破 number 精度限制 | ES2020 新增 |

### 引用类型（1种）— 栈里存地址，堆里存数据

```
                        Object (引用类型)
                              │
          ┌───────────────────┼───────────────────┐
          │                   │                   │
          ▼                   ▼                   ▼
       普通对象             Array             Function
       { ... }            [ ... ]           function(){}
          │
    ┌─────┴─────┐
    ▼           ▼
   Date       RegExp
  Map/Set    WeakMap...
```

## 三、存储方式 → 复制行为（核心推导）

### 📊 复制行为可视化

```
【原始类型复制】                     【引用类型复制】

  栈内存                              栈内存          堆内存
┌─────────┐                        ┌─────────┐    ┌─────────────┐
│  a = 1  │ ← 直接复制值            │ obj1=0x1│───▶│ { x: 1 }    │
├─────────┤                        ├─────────┤    └─────────────┘
│  b = 1  │ ← b 是独立的副本         │ obj2=0x1│───────┘
└─────────┘                        └─────────┘     ↑
                                    两个变量指向同一块内存！
修改 b 不影响 a                      修改 obj2 会影响 obj1
```

### 💻 经典面试代码

```javascript
// ===== 原始类型：复制值 =====
let a = 1;
let b = a;      // 复制值本身
b = 2;
console.log(a); // 1（互不影响）

// ===== 引用类型：复制地址 =====
let obj1 = { x: 1 };
let obj2 = obj1;  // 复制的是地址，不是对象本身
obj2.x = 2;
console.log(obj1.x); // 2（指向同一块内存，相互影响！）

// ===== 面试高频：函数参数传递 =====
function changeValue(num, obj) {
    num = 100;      // 修改的是副本
    obj.name = "changed";  // 修改的是同一个对象
}

let number = 1;
let person = { name: "original" };
changeValue(number, person);

console.log(number);      // 1（不变）
console.log(person.name); // "changed"（被修改了！）
```

> **本质洞察**：这不是「特性」，而是存储方式的**必然结果**。

## 四、类型判断的本质

### 📊 四种判断方法对比

```
                    类型判断方法对比
┌────────────────┬─────────────────┬────────────────┐
│     方法        │      原理       │      局限      │
├────────────────┼─────────────────┼────────────────┤
│    typeof      │ 读取类型标签     │ null→"object"  │
├────────────────┼─────────────────┼────────────────┤
│  instanceof    │ 沿原型链查找     │ 只能判断引用类型 │
├────────────────┼─────────────────┼────────────────┤
│ Object.prototype│ 读取[Class](./Class.md)  │ 写法繁琐       │
│   .toString    │    标签         │                │
├────────────────┼─────────────────┼────────────────┤
│  constructor   │ 查看构造函数     │ 可被篡改       │
└────────────────┴─────────────────┴────────────────┘
```

### 💻 经典面试代码

```javascript
// ===== typeof：快速但有坑 =====
typeof 42;           // "number"
typeof "hello";      // "string"
typeof true;         // "boolean"
typeof undefined;    // "undefined"
typeof Symbol();     // "symbol"
typeof 10n;          // "bigint"

// ⚠️ 著名的 bug
typeof null;         // "object" ← 历史遗留问题！
typeof [];           // "object" ← 无法区分数组
typeof function(){}; // "function" ← 特殊处理

// ===== instanceof：检查原型链 =====
[] instanceof Array;           // true
[] instanceof Object;          // true（数组也是对象）
"hello" instanceof String;     // false（原始类型不行！）

// ===== 最准确：Object.prototype.toString =====
Object.prototype.toString.call(null);       // "[object Null]"
Object.prototype.toString.call([]);         // "[object Array]"
Object.prototype.toString.call(function(){}); // "[object Function]"
Object.prototype.toString.call(new Date()); // "[object Date]"

// ===== 封装成工具函数 =====
function getType(value) {
    return Object.prototype.toString.call(value).slice(8, -1).toLowerCase();
}
getType(null);     // "null"
getType([]);       // "array"
getType({});       // "object"
```

```
        └──────────────┬──────────────┘
```

### 转换规则速查表

```
┌─────────────┬─────────────┬─────────────┬─────────────┐
│   原始值     │  → Number   │  → String   │  → Boolean  │
├─────────────┼─────────────┼─────────────┼─────────────┤
```

### 💻 经典面试代码

```javascript
// ===== + 运算符的双重身份 =====

// 1. 一元 + ：转数字
+"42"       // 42
+true       // 1
+[]         // 0
+{}         // NaN

// 2. 二元 + ：有字符串就拼接
1 + "2"     // "12"（数字变字符串）
"1" + 2     // "12"
1 + 2       // 3（都是数字就加法）

// ===== 经典陷阱题 =====
[] + []     // ""（两个空数组转字符串拼接）
[] + {}     // "[object Object]"
{} + []     // 0（{} 被解析为代码块，实际是 +[]）

// ===== == 的隐式转换 =====
"1" == 1    // true（字符串转数字）
true == 1   // true（布尔转数字）
null == undefined  // true（特殊规则）
[] == false // true（[] → "" → 0, false → 0）

// ===== Falsy 值（记住这6个） =====
Boolean(false);     // false
Boolean(0);         // false
Boolean("");        // false
Boolean(null);      // false
Boolean(undefined); // false
Boolean(NaN);       // false
// 其他所有值都是 truthy！包括 [] 和 {}
```

## 六、特殊值的设计哲学

### 1️⃣ `0.1 + 0.2 !== 0.3`

```
            二进制浮点数的局限
┌─────────────────────────────────────────┐
│  十进制 0.1                              │
│     ↓                                   │
│  二进制 0.0001100110011...（无限循环）    │
│     ↓                                   │
│  截断存储 → 精度丢失                      │
└─────────────────────────────────────────┘
```

```javascript
// 问题
0.1 + 0.2 === 0.3;  // false
0.1 + 0.2;          // 0.30000000000000004

// ✅ 解决方案
Math.abs(0.1 + 0.2 - 0.3) < Number.EPSILON;  // true
// 或者转整数计算
(0.1 * 10 + 0.2 * 10) / 10 === 0.3;  // true
```

### 2️⃣ `typeof null === "object"`

```
    JavaScript 第一版的 Bug
┌─────────────────────────────────────┐
│  类型标签设计：                       │
│  - 000: object                      │
│  - 001: integer                     │
│  - 010: double                      │
│  - 100: string                      │
│  - 110: boolean                     │
│                                     │
│  null 的值：全是 0                   │
│  → 被误判为 object！                 │
└─────────────────────────────────────┘
```

```javascript
typeof null;  // "object" ← 历史遗留 bug，无法修复

// ✅ 正确判断 null
value === null;
Object.prototype.toString.call(null);  // "[object Null]"
```

### 3️⃣ `NaN !== NaN`

```javascript
// IEEE 754 规定：NaN 不等于任何值，包括自己
NaN === NaN;  // false
NaN == NaN;   // false

// ✅ 判断 NaN 的方法
Number.isNaN(NaN);     // true（推荐）
Object.is(NaN, NaN);   // true
```

## 七、比较操作的本质

### 📊 三种比较方式

```
         ==                    ===                 Object.is
          │                     │                      │
          ▼                     ▼                      ▼
    先类型转换              不转换直接比较          不转换 + 特殊处理
    再比较值               类型不同就 false        NaN===NaN ✓
                                                  +0 !== -0 ✓
```

### 💻 经典面试代码

```javascript
// ===== == vs === =====
1 == "1";    // true（隐式转换）
1 === "1";   // false（类型不同）

null == undefined;   // true（特殊规则）
null === undefined;  // false

// ===== Object.is 的特殊处理 =====
NaN === NaN;           // false
Object.is(NaN, NaN);   // true ✅

+0 === -0;             // true
Object.is(+0, -0);     // false ✅

// ===== 最佳实践 =====
// 1. 默认使用 ===
// 2. 需要处理 NaN 时用 Object.is
// 3. 避免使用 ==（除非明确需要类型转换）
```

## 八、深拷贝与浅拷贝

### 📊 可视化理解

```
【浅拷贝】                           【深拷贝】

原对象                               原对象
┌─────────────┐                     ┌─────────────┐
│ a: 1        │                     │ a: 1        │
│ b: ──────┐  │                     │ b: ──────┐  │
└──────────│──┘                     └──────────│──┘
           │                                   │
           ▼                                   ▼
      ┌─────────┐                        ┌─────────┐
      │ x: 10   │                        │ x: 10   │
      └─────────┘                        └─────────┘
           ▲                                   
           │                                   
新对象     │                           新对象
┌──────────│──┐                     ┌─────────────┐
│ a: 1     │  │                     │ a: 1        │
│ b: ──────┘  │ ← 共享同一个对象！    │ b: ──────┐  │
└─────────────┘                     └──────────│──┘
                                               │
                                               ▼
                                          ┌─────────┐
                                          │ x: 10   │ ← 完全独立的副本
                                          └─────────┘
```

### 💻 经典面试代码

```javascript
// ===== 浅拷贝方法 =====
// 1. 展开运算符
const shallow1 = { ...original };

// 2. Object.assign
const shallow2 = Object.assign({}, original);

// 3. 数组方法
const arrShallow = [...arr];
const arrShallow2 = arr.slice();

// ===== 深拷贝方法 =====

// 1. JSON 方法（简单但有限制）
const deep1 = JSON.parse(JSON.stringify(original));
// ⚠️ 限制：无法处理 function、undefined、Symbol、循环引用

// 2. structuredClone（现代浏览器）
const deep2 = structuredClone(original);
// ⚠️ 限制：无法处理 function、Symbol

// 3. 手写递归深拷贝（面试必会）
function deepClone(obj, map = new WeakMap()) {
    // 基本类型直接返回
    if (obj === null || typeof obj !== 'object') {
        return obj;
    }
    
    // 处理循环引用
    if (map.has(obj)) {
        return map.get(obj);
    }
    
    // 处理特殊对象
    if (obj instanceof Date) return new Date(obj);
    if (obj instanceof RegExp) return new RegExp(obj);
    
    // 创建新对象/数组
    const clone = Array.isArray(obj) ? [] : {};
    map.set(obj, clone);
    
    // 递归拷贝
    for (let key in obj) {
        if (obj.hasOwnProperty(key)) {
            clone[key] = deepClone(obj[key], map);
        }
    }
    
    return clone;
}
```

## 十、面试速查清单

### ✅ 必记要点

| 知识点 | 要点 |
|--------|------|
| 数据类型 | 7 原始 + 1 引用 = 8 种 |
| 存储位置 | 原始→栈，引用→栈存地址+堆存值 |
| 复制行为 | 原始复制值，引用复制地址 |
| typeof null | 返回 "object"（历史 bug） |
| NaN 特性 | NaN !== NaN，用 Number.isNaN() |
| 浮点数精度 | 0.1+0.2 !== 0.3，用 EPSILON |
| 类型判断 | toString.call() 最准确 |
| Falsy 值 | false, 0, "", null, undefined, NaN |

### 🎯 面试高频问题

1. **基本类型和引用类型的区别？** → 存储方式不同
2. **深拷贝和浅拷贝的区别？** → 是否递归复制嵌套对象
3. **typeof 能判断哪些类型？** → 除 null 外的原始类型 + function
4. **== 和 === 的区别？** → 是否进行类型转换
5. **如何判断数组？** → Array.isArray() 或 toString.call()

---

## 🔑 核心奥义

> **记住这条逻辑链，一切问题迎刃而解：**
>
> **存储方式 → 复制行为 → 比较行为 → 类型判断方法**
>
> JavaScript 的数据类型没有「魔法」，所有行为都是内存模型的**必然推演**。
