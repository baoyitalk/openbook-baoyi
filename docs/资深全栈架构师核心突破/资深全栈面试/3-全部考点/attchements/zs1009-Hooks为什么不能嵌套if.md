# useState 底层内存模型解析
本文基于 JS 栈/堆内存模型 + React Hooks 底层实现，拆解 `const [isPlaying, setIsPlaying] = useState(false);` 的内存存储逻辑，并通过 ASCII 可视化完整内存结构。

## 一、前置核心内存规则
### 1. JS 内存分区（不可动摇的基础）
| 内存区域     | 存储内容                                           | 特性               |
| -------- | ---------------------------------------------- | ---------------- |
| 栈（Stack） | 基本类型值（boolean/number/string 等）、函数调用栈、引用类型的内存地址 | 轻量、高速、大小固定       |
| 堆（Heap）  | 复杂对象（Fiber 节点、Hook 节点、函数对象、数组/对象等）             | 体积大、可动态扩展、垃圾回收目标 |

### 2. React Hooks 底层实现规则
- 每个组件对应一个 **Fiber 节点**（存储在堆中），Fiber 节点维护一个 **Hooks 单向链表**；
- 每调用一次 `useState`，会在 Hooks 链表中创建一个 **Hook 节点**，保存该 state 的值、更新队列等核心信息；
- `useState` 返回的 `[state, setter]` 对：
  - `state`：基本类型直接存在栈中，引用类型栈中存堆地址；
  - `setter`：栈中存函数地址，堆中存绑定了当前 Hook 节点的更新函数（通过闭包关联）。

## 二、首次渲染时的内存模型（ASCII 可视化）
### 1. 整体内存结构
```text
┌──────────────────────────────────────── 栈 (Stack) ────────────────────────────────────────┐
│ 变量名          存储内容                          类型/说明                                  │
│ ────────────── ─────────────────────────────── ────────────────────────────────────────── │
│ isPlaying      false                             基本类型（boolean），直接存在栈中           │
│ setIsPlaying   0x123456（函数地址）              引用类型，栈中存地址，指向堆中的setter函数  │
│ 组件执行上下文  Fiber节点地址（0x789012）         指向堆中的组件Fiber节点                    │
└─────────────────────────────────────────────────────────────────────────────────────────────┘
                                            ↓ 引用
┌──────────────────────────────────────── 堆 (Heap) ─────────────────────────────────────────┐
│ 地址          存储内容（Fiber节点 + Hooks链表）                                            │
│ ──────────── ──────────────────────────────────────────────────────────────────────────── │
│ 0x789012     Fiber节点（对应当前VideoPlayer组件）                                          │
│              ├─ type: VideoPlayer（组件类型）                                              │
│              ├─ stateNode: null（组件实例）                                                │
│              └─ memoizedState: 0xABCDEF（指向第一个Hook节点）                              │
│                                                                                            │
│ 0xABCDEF     Hook节点（对应useState(false)）                                               │
│              ├─ memoizedState: false（当前state值，基本类型直接存在堆中）                   │
│              ├─ queue: 0xDEF123（更新队列，保存setIsPlaying的更新操作）                    │
│              ├─ next: null（下一个Hook节点，如useState(comments)的Hook节点）               │
│              └─ tag: 0（标记为StateHook）                                                  │
│                                                                                            │
│ 0xDEF123     更新队列（Update Queue）                                                     │
│              ├─ pending: null（待执行的更新操作，首次渲染为空）                            │
│              └─ dispatch: 0x123456（指向setIsPlaying函数）                                │
│                                                                                            │
│ 0x123456     setIsPlaying函数对象                                                          │
│              ├─ [[scope]]: 闭包作用域（绑定当前Hook节点0xABCDEF）                          │
│              └─ 逻辑：修改Hook节点的memoizedState + 触发组件重渲染                          │
└─────────────────────────────────────────────────────────────────────────────────────────────┘
```

### 2. 关键细节解释
- **isPlaying（栈存储）**：  
  `false` 是基本类型（boolean），直接存储在栈中，组件执行时可快速访问；若 state 是复杂类型（如 `useState({a:1})`），栈中会存储堆对象的地址（如 `0xXXXXXX`），堆中存储具体对象。
- **Hook 节点（堆存储）**：  
  `memoizedState` 保存当前稳定的 state 值（React 持久化状态的核心），`queue` 维护该 state 的更新队列，`next` 串联后续 hooks（保证调用顺序）。
- **setIsPlaying（栈+堆）**：  
  栈中存储函数地址，堆中存储函数对象；函数通过闭包绑定对应的 Hook 节点，确保调用 `setIsPlaying` 时能精准修改目标 state。

## 三、调用 setIsPlaying(true) 后的内存变化
### 1. 内存结构变化（ASCII 简化版）
```text
┌──────────────────────── 栈 (Stack) ────────────────────────┐
│ isPlaying: true （组件重渲染后，栈中值同步更新）           │
│ setIsPlaying: 0x123456（地址不变，函数对象复用）          │
└───────────────────────────────────────────────────────────┘
                          ↓ 引用
┌──────────────────────── 堆 (Heap) ────────────────────────┐
│ Hook节点（0xABCDEF）:                                     │
│   memoizedState: true （核心变化：state值更新为true）      │
│   queue: {                                                │
│     pending: 0xGHI789（新增更新对象：{action: ()=>true}） │
│   }                                                       │
└───────────────────────────────────────────────────────────┘
```

### 2. 核心执行逻辑
1. 调用 `setIsPlaying(true)` → React 在对应 Hook 节点的 `queue` 中新增「更新对象」（记录要更新的状态）；
2. React 触发组件重渲染 → 重新执行组件函数，遍历 Hooks 链表，从 Hook 节点的 `memoizedState` 读取最新值（`true`）；
3. 栈中的 `isPlaying` 变量同步更新为 `true`，最终映射到 DOM 完成视图更新。

## 四、核心总结
1. **基本类型 state**：栈中存储值（组件执行快速访问），堆中 Hook 节点的 `memoizedState` 也存储值（React 持久化状态），双份存储保证性能与状态稳定；
2. **引用类型 state**：栈中存储堆地址，堆中同时存储 Hook 节点和具体对象；
3. **setter 函数**：地址存在栈中，函数对象存在堆中，通过闭包绑定 Hook 节点，保证更新精准性；
4. **hooks 调用顺序**：React 依赖 Hooks 链表的顺序识别每个 `useState`，这是「hooks 不能写在 if/循环中」的底层原因（破坏链表顺序会导致 state 错乱）。 ^1jx6pt

## 附录：关键术语解释
| 术语       | 说明                                              |
| -------- | ----------------------------------------------- |
| Fiber 节点 | React 组件的底层表示，存储组件类型、状态、子节点等信息                  |
| Hooks 链表 | 每个组件的 hooks 按调用顺序形成的单向链表，是 React 管理 hooks 的核心结构 |
| 闭包       | setter 函数通过闭包绑定 Hook 节点，确保更新操作能精准定位目标 state     |
| 更新队列     | 存储 state 的更新操作，React 批量处理更新队列以优化性能              |
