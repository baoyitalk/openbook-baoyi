你的这个疑问精准命中了「简化写法」和「严格分层」的边界！先给核心结论：
这段代码里 `useEffect` 直接写 `setComments(data)` 是**简化版写法**（为了新手易理解），并非“严格分层的最优实践”——严格来说，哪怕是初始化加载评论，也该让副作用层调用行为层的函数，而非直接写 `setXxx`。

### 一、为什么会有“简化写法”？
在组件挂载加载数据这种「简单初始化场景」中，直接写 `setComments(data)` 是行业内的常见做法，核心原因：
1. **代码简洁**：避免为了一行 `setComments` 额外抽一个行为层函数，减少冗余；
2. **逻辑单一**：初始化加载评论的逻辑无“数据校验、默认值处理”等复杂操作，直接赋值足够清晰；
3. **新手友好**：不用额外理解“行为层函数+副作用调用”的嵌套逻辑。

但这并不违背分层的核心思想——分层的本质是「**让核心业务逻辑（状态修改规则）集中**」，而非“机械禁止所有场景的setXxx”。

### 二、严格分层的写法（合规版，复杂场景必用）
如果加载评论后需要做「数据校验、默认值处理、格式转换」等复杂逻辑，就必须把 `setComments` 抽成行为层函数，副作用层只调用这个函数：

```javascript
// ========== 行为层：集中管理comments的修改（唯一入口） ==========
// 1. 初始化评论（带数据校验/默认值处理）
const initComments = useCallback((rawData) => {
  // 行为层：统一处理数据规则（核心业务逻辑）
  const validData = Array.isArray(rawData) ? rawData : []; // 空值校验
  const formattedData = validData.map(item => ({
    id: item.id || Date.now(), // 补全默认id
    text: item.text || '',
    likes: item.likes || 0
  }));
  setComments(formattedData); // 行为层独占setXxx
}, []);

// ========== 副作用层：仅做外部交互，调用行为层函数 ==========
useEffect(() => {
  const fetchComments = async () => {
    try {
      const res = await fetch('/api/comments');
      const data = await res.json();
      isSyncingRef.current = true;
      initComments(data); // 副作用层不直接写setComments，调用行为层函数
    } catch (err) {
      console.error('加载评论失败：', err);
      initComments([]); // 兜底：调用行为层设置空数组
    } finally {
      isSyncingRef.current = false;
    }
  };
  fetchComments();
}, [initComments]); // 依赖行为层函数（已缓存，引用稳定）
```

### 三、核心区别：简化写法 vs 严格写法
| 场景                | 简化写法（直接setComments） | 严格写法（调用行为层函数） |
|---------------------|-----------------------------|----------------------------|
| 适用场景            | 简单初始化（无数据处理）| 复杂逻辑（校验/格式化/兜底） |
| 分层合规性          | 「宽松合规」（逻辑集中）| 「严格合规」（职责分离）|
| 可维护性            | 简单场景够用                | 复杂场景易扩展（规则统一） |

### 四、总结（关键原则）
1. **分层的核心是“逻辑集中”，而非“机械禁止”**：
   - 简单场景（如初始化加载数据）：副作用层直接写 `setXxx` 是可接受的，只要「所有修改该状态的逻辑最终能收敛到一处」；
   - 复杂场景（如带校验/格式化/多场景修改）：必须把 `setXxx` 抽成行为层函数，副作用层只调用，保证规则统一。
2. **新手落地建议**：
   - 先保证“功能正确+逻辑集中”，再追求“严格分层”；
   - 当同一个 `setXxx` 出现在多个地方（比如初始化、添加、编辑评论都改comments），立刻抽行为层函数，避免规则分散。

你看到的 `useEffect` 里写 `setComments`，是「简化版的宽松写法」，目的是降低理解成本；在实际复杂项目中，一定要像“严格写法”那样，把状态修改逻辑抽成行为层函数——这才是分层的最终目的：**让所有修改state的规则都在行为层，查bug时只看一处**。
