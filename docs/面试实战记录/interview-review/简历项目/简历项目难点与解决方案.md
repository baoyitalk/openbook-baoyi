# 面试项目应答记录（精简口语化，适配面试）

## 一、亚信科技（中国移动项目）

1. 项目难点：H5需适配APP和小程序双端，通信规则不统一，且多业务线组件杂乱、性能卡顿。

2. 解决方法：自研JSBridge协议实现双端复用，封装统一组件库，结合接口聚合、懒加载优化性能。

3. 解决方案细节：自定义统一通信格式和回调机制，封装H5适配层自动判断运行环境，适配APP和小程序原生通信方式，增加超时、重试异常处理，实现一套H5代码双端复用。

  

## 二、神州数码（光大银行项目）

1. 项目难点：多系统接口差异大、数据格式不统一，千万级结算数据渲染卡顿。

2. 解决方法：设计统一数据适配层，开发Node.js BFF层，配合SQL索引优化和虚拟滚动。

3. 解决方案细节：适配层屏蔽各系统接口差异，BFF层聚合多后端接口减少前端请求，SQL索引优化提升查询速度，虚拟滚动解决大数据渲染卡顿，保障系统流畅运行。

# 项目拷问




## 现在跨端框架/JSBridge这么多，为什么你还要自研？

  

## 面试满分回答（口语化、简洁、有说服力）

因为**业务场景特殊 + 成本 + 稳定性**三个核心原因：

1. **项目是存量H5**，不是新项目，不能直接上 uni-app / Taro 重写，改造成本极高、风险大；

2. **中国移动APP + 小程序双端原生规则不开放、不统一**，现成框架不兼容、无法调用内部原生能力；

3. 自研只需要**封装一层轻量通信协议**，体积小、无依赖、稳定性可控，能**最小成本实现一套H5跑双端**，比引入重型跨端框架更轻、更快、更稳。
