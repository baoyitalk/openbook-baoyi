# 10 性能优化专项（费曼一问一答）

> 适用：性能优化专项面、晋升答辩、项目复盘。

## Q1：性能优化第一步为什么不是“改代码”？
**A（费曼四段）**
1. 学习理解：性能优化先定位瓶颈，再做动作，否则容易做无效优化。
2. 大白讲解：你不先测，就不知道慢在下载、接口、渲染还是脚本执行。先拿 Lighthouse、Performance、RUM 建基线，再决定优化顺序。
3. 漏洞卡点：上来就“加缓存、拆包”，最后指标没明显变化。
4. 压缩总结：先测量，后优化，最后验证。

## Q2：Core Web Vitals 面试怎么答？
**A（费曼四段）**
1. 学习理解：LCP 看加载主内容速度，INP 看交互响应，CLS 看布局稳定性。
2. 大白讲解：用户最在意三件事：多久能看到主要内容、点击后多久有反应、页面会不会乱跳。三项指标刚好对应这三件事。
3. 漏洞卡点：只会念指标名，不会说优化动作和结果。
4. 压缩总结：Vitals 是用户体验的量化坐标。

## Q3：包体优化的主线是什么？
**A（费曼四段）**
1. 学习理解：包体优化核心是“首屏少加载、重复少加载、变化少加载”。
2. 大白讲解：路由拆分减少首屏包；公共依赖拆 chunk 减少重复；`contenthash` 让未变资源长期缓存命中。
3. 漏洞卡点：只关心总包大小，不关心首屏关键路径。
4. 压缩总结：优化关键路径比优化总量更重要。

## Q4：图片优化为什么收益常常最大？
**A（费曼四段）**
1. 学习理解：很多页面流量大头是图片，图片策略直接影响首屏和带宽成本。
2. 大白讲解：同一张图做格式切换（WebP/AVIF）、尺寸裁剪、懒加载、CDN 自适应，收益往往比你改几行 JS 更明显。
3. 漏洞卡点：原图直传、无尺寸声明导致布局抖动和慢加载。
4. 压缩总结：图片是性能大头，先治图片常见效最快。

## Q5：长任务（Long Task）怎么治理？
**A（费曼四段）**
1. 学习理解：主线程连续执行超过约 50ms 的任务会阻塞交互。
2. 大白讲解：重计算要拆分、分片、异步化，必要时丢给 Web Worker，避免用户点击无响应。
3. 漏洞卡点：只优化网络，不优化主线程计算。
4. 压缩总结：减少主线程阻塞，交互才会顺。

## Q6：列表卡顿优化怎么讲？
**A（费曼四段）**
1. 学习理解：列表卡顿本质是一次渲染节点过多和频繁重排重绘。
2. 大白讲解：超长列表用虚拟列表，只渲染可视区域；滚动事件做节流；避免每次滚动触发昂贵布局计算。
3. 漏洞卡点：一次性渲染几千行 DOM，浏览器必卡。
4. 压缩总结：按视口渲染 + 控制频率 = 列表流畅。

## Q7：缓存策略怎么形成闭环？
**A（费曼四段）**
1. 学习理解：缓存不是“越久越好”，要结合资源变化频率和失效策略设计。
2. 大白讲解：静态资源走强缓存 + 版本号；动态数据走协商缓存或服务端缓存；上线后看命中率和回源率持续调优。
3. 漏洞卡点：缓存配了但没监控，命中差也没人知道。
4. 压缩总结：缓存要有策略、有监控、有复盘。

## Q8：怎么证明性能优化真的有价值？
**A（费曼四段）**
1. 学习理解：价值要用前后对照数据证明，而不是“感觉更快”。
2. 大白讲解：至少给三组数据：优化前、优化后、观察周期。比如 LCP 下降、错误率下降、转化率提升，才有业务说服力。
3. 漏洞卡点：只报动作，不报结果。
4. 压缩总结：可量化对照，是性能成果的唯一硬通货。
