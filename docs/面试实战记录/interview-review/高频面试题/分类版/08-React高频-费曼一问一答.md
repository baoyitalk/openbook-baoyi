# 08 React高频（费曼一问一答）

> 适用：React 面试主线回答，强调“为什么这样设计”。

## Q1：React Diff 核心原理怎么讲？
**A（费曼四段）**
1. 学习理解：Diff 目标是减少真实 DOM 操作，规则是同层比较、类型变化直接替换、列表依赖 key 复用。
2. 大白讲解：React 不会暴力重建整页，而是尽量复用旧节点。列表里 `key` 稳定，复用就准确；`key` 乱用（尤其 index）就会节点错位、状态串台。
3. 漏洞卡点：只背“虚拟 DOM 快”，说不出 key 不稳定的真实后果。
4. 压缩总结：Diff 的本质是最小化真实 DOM 变更。

## Q2：Fiber 引入解决了什么痛点？
**A（费曼四段）**
1. 学习理解：Fiber 把大更新拆成可中断小任务，让高优先级交互先执行，避免主线程长时间卡死。
2. 大白讲解：以前一次更新可能要一直算到底，用户点击都没响应。Fiber 相当于把大活拆段，做到“边算边让路”，输入、滚动体验更稳。
3. 漏洞卡点：把 Fiber 说成“替代 Diff 算法”。
4. 压缩总结：Diff 决定改哪里，Fiber 决定何时改、先改谁。

## Q3：useEffect 最容易踩的坑有哪些？
**A（费曼四段）**
1. 学习理解：核心风险是依赖数组不准确和副作用清理不完整。
2. 大白讲解：依赖漏写会读到旧闭包值；依赖乱写会无限触发；请求、订阅、监听不清理会造成内存泄漏和重复执行。
3. 漏洞卡点：只会“加空数组”，不会解释时机和 cleanup。
4. 压缩总结：依赖要完整，清理要彻底。

## Q4：props、context、ref 怎么分工？
**A（费曼四段）**
1. 学习理解：props 显式传值，context 跨层共享，ref 存不触发渲染的可变引用或 DOM。
2. 大白讲解：优先 props，只有跨多层且相对稳定的数据才放 context。`ref` 适合计时器、DOM、上一次值，不适合当状态管理替代品。
3. 漏洞卡点：把高频变化状态全塞 context，引发大面积重渲染。
4. 压缩总结：先 props，再 context，ref 只做“非渲染数据”。

## Q5：React 渲染性能优化你怎么落地？
**A（费曼四段）**
1. 学习理解：优化不是“到处加 memo”，而是先定位热点，再收紧更新边界。
2. 大白讲解：先用 Profiler 找重渲染源头，再按需用 `React.memo`、`useMemo`、`useCallback`，同时做组件拆分和列表虚拟化。
3. 漏洞卡点：过度优化导致代码复杂，收益不明显。
4. 压缩总结：先测量再优化，优化只做在热点上。

## Q6：setState 为什么“看起来异步”？
**A（费曼四段）**
1. 学习理解：框架会做批处理和调度，更新不会每次调用都立刻反映到视图。
2. 大白讲解：你调用更新方法后，React 常先收集同一轮更新再统一提交，所以“刚 set 完马上读值”常拿到旧值。
3. 漏洞卡点：更新后立刻读 DOM/状态，导致判断错误。
4. 压缩总结：状态更新有调度，读值要看时机。

## Q7：受控组件和非受控组件怎么取舍？
**A（费曼四段）**
1. 学习理解：受控组件由 React 状态驱动，非受控组件由 DOM 自身保存值。
2. 大白讲解：表单校验复杂、联动多就用受控；简单输入、性能敏感可局部非受控，通过 ref 取值。
3. 漏洞卡点：全受控导致输入延迟，全非受控又难统一校验。
4. 压缩总结：复杂交互偏受控，简单高性能场景可非受控。

## Q8：React 面试为什么常和事件循环一起问？
**A（费曼四段）**
1. 学习理解：状态提交、Promise 回调、定时器回调都受任务队列时序影响。
2. 大白讲解：同样一段代码，放在微任务和宏任务里执行顺序会不同，直接影响你对 UI 更新时机的判断。
3. 漏洞卡点：只懂 React API，不懂 JS 调度时序。
4. 压缩总结：React 问题很多是“时序问题”，底层绕不开事件循环。
