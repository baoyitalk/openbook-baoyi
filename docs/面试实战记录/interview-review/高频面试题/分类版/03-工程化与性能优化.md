# 03 工程化与性能优化（连环追问）

## 1. webpack 和 vite 区别
Q1：一句话区别？  
A1：Vite 开发启动更快，webpack 在复杂老项目上更稳。

Q2：Vite 为什么快？  
A2：原生 ESM 按需加载，不走全量打包。

Q3：怎么选？  
A3：新项目优先 Vite，历史包袱重用 webpack。

## 2. webpack 做过哪些优化
Q1：优化方向？  
A1：提速、减包、提升缓存命中。

Q2：提速怎么做？  
A2：持久化缓存、多进程、精简 loader 范围。

Q3：减包怎么做？  
A3：拆包、按需加载、tree-shaking、第三方依赖治理。

## 3. 首屏加载怎么优化（工程视角）
Q1：第一步？  
A1：先监控定位瓶颈，再对症下药。

Q2：通用方案？  
A2：路由懒加载、关键资源预加载、接口并行、缓存策略。

Q3：验证指标？  
A3：LCP/FCP/TTI + 线上真实用户数据。

## 4. SSR 改造
Q1：SSR 价值？  
A1：首屏更快可见，SEO 更友好。

Q2：改造关注点？  
A2：数据预取、同构边界、hydrate 一致性、缓存。

Q3：风险点？  
A3：服务端压力、水合不一致，需要监控和降级。

## 5. JSBridge 与性能的关系（重复知识点）
Q1：JSBridge 为什么跟性能也有关？  
A1：统一通信后可减少重复封装和无效调用，交互链路更稳定。

Q2：怎么讲成“工程收益”？  
A2：减少端差异 bug，缩短排查和迭代时间。

## 6. Fiber/Diff（工程化场景下会重复问）
Q1：为啥这里也问 Fiber？  
A1：因为性能优化本质也在优化渲染调度和更新成本。

Q2：一句话回答？  
A2：Diff 决定改哪里，Fiber 决定何时改、先改谁。
