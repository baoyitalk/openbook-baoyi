# 11 场景题（费曼一问一答）

> 适用：项目复盘题、问题排查题、面试官追“你真实怎么做”的场景。

## Q1：线上首屏突然变慢，你第一步怎么做？
**A（费曼四段）**
1. 学习理解：先止损和定位，再优化；不能一上来盲改。
2. 大白讲解：先确认是不是全量用户受影响，再看最近发版和监控。定位到是资源、接口、渲染哪一段变慢，再做最小回滚或热修复。
3. 漏洞卡点：不看监控直接改代码，排查路径混乱。
4. 压缩总结：先定影响范围，再按链路定位，再精准处理。

## Q2：历史系统迁移为什么常用渐进迁移？
**A（费曼四段）**
1. 学习理解：渐进迁移核心是风险分摊和可回滚，避免一次性改造引发系统级事故。
2. 大白讲解：把大迁移拆成小批次，先低风险模块试点，有问题随时回滚；稳定后再扩大范围，保证业务不断。
3. 漏洞卡点：只说“分阶段”，不说分阶段标准和回滚方案。
4. 压缩总结：渐进迁移=小步快跑+可灰度+可回滚。

## Q3：接口 403 激增，你怎么排查？
**A（费曼四段）**
1. 学习理解：403 多是权限或风控拒绝，优先查鉴权链路和请求来源变化。
2. 大白讲解：先核对 token/cookie 是否过期，再看网关策略、IP 白名单、请求头是否被改，最后比对发布前后差异。
3. 漏洞卡点：把 403 当后端宕机处理，方向一开始就错。
4. 压缩总结：403 先查身份和策略，不是先查服务器崩溃。

## Q4：灰度发布后错误率上升，你怎么决策回滚？
**A（费曼四段）**
1. 学习理解：回滚决策看错误率阈值、影响范围、可恢复性，不看个人主观判断。
2. 大白讲解：提前定义“熔断线”，超过就立即回滚。先保业务可用，再开复盘会议定位根因和修复计划。
3. 漏洞卡点：没有预设阈值，团队靠临场拍脑袋。
4. 压缩总结：有阈值就有决策速度，先止血再复盘。

## Q5：跨端能力不一致时，怎么保证业务开发效率？
**A（费曼四段）**
1. 学习理解：核心做法是协议收口，把端差异封装在适配层，业务只用统一 API。
2. 大白讲解：iOS 和 Android 参数不同、回调不同，业务层不该重复兼容。把差异收在 JSBridge 适配层后，业务开发心智明显下降。
3. 漏洞卡点：让每个业务自己兼容，后期维护和排查成本爆炸。
4. 压缩总结：端差异要下沉到底层，业务层只看统一接口。

## Q6：线上报错率上升但本地复现不了，怎么办？
**A（费曼四段）**
1. 学习理解：这类问题通常是环境差异导致，必须依赖日志、埋点和回放定位。
2. 大白讲解：先看报错分布（机型、系统、地域、版本），再还原相同环境。必要时加临时日志和开关做二次采样。
3. 漏洞卡点：只在本地反复点点点，不做数据化定位。
4. 压缩总结：复现不了就靠观测系统，先找共性再定位根因。

## Q7：需求时间非常紧，你怎么保质交付？
**A（费曼四段）**
1. 学习理解：核心是范围管理，不是无上限加班。
2. 大白讲解：先拆“必须有”和“可延期”，优先上线主流程；同时补自动化回归和关键监控，减少赶工引发的线上事故。
3. 漏洞卡点：只追速度不控范围，最后返工更慢。
4. 压缩总结：紧急交付靠优先级治理，不靠硬扛。

## Q8：面试官问“你怎么证明价值”，你怎么答？
**A（费曼四段）**
1. 学习理解：价值证明要有指标、基线、对照和周期。
2. 大白讲解：回答结构固定：我做了什么动作，影响了哪个指标，提升了多少，观察了多久。没有数据就不是完整价值闭环。
3. 漏洞卡点：只讲过程故事，不给结果数字。
4. 压缩总结：结果要量化，叙述要可验证。
