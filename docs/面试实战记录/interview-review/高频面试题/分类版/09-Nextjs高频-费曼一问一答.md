# 09 Next.js高频（费曼一问一答）

> 适用：Next.js 岗位和“SSR/SEO/性能”方向面试。

## Q1：CSR、SSR、SSG、ISR 怎么区分？
**A（费曼四段）**
1. 学习理解：四者本质是“页面在什么时候生成”。CSR 在浏览器生成，SSR 每次请求服务端生成，SSG 构建时生成，ISR 是静态页按周期增量再生。
2. 大白讲解：要实时强一致用 SSR；内容长期稳定用 SSG；既想静态快又要定期更新用 ISR；纯后台系统不重 SEO 可用 CSR。
3. 漏洞卡点：只会背缩写，不会按业务场景选型。
4. 压缩总结：按“实时性 + SEO + 成本”三维选渲染策略。

## Q2：App Router 和 Pages Router 的核心差异是什么？
**A（费曼四段）**
1. 学习理解：App Router 基于 React Server Components 和嵌套路由，数据获取更靠近组件；Pages Router 是传统 page 级路由与数据函数。
2. 大白讲解：App Router 更现代，布局、加载、错误边界都按目录就近管理；Pages Router 更直观，历史项目迁移成本低。
3. 漏洞卡点：混淆两套路由的数据获取方式，导致代码放错层。
4. 压缩总结：新项目优先 App Router，老项目按迁移成本评估。

## Q3：Server Component 和 Client Component 怎么分工？
**A（费曼四段）**
1. 学习理解：Server Component 在服务端渲染，不打包到浏览器；Client Component 负责交互，需要 `use client`。
2. 大白讲解：能在服务端算完的内容尽量放 Server Component，减少前端包体；需要点击、输入、浏览器 API 的再放 Client Component。
3. 漏洞卡点：把大量纯展示组件写成 Client，白白增加 JS 包。
4. 压缩总结：交互放客户端，静态展示优先服务端。

## Q4：Next.js 数据缓存和 revalidate 怎么回答？
**A（费曼四段）**
1. 学习理解：Next 的 `fetch` 支持缓存和再验证，能在性能与实时性间平衡。
2. 大白讲解：不需要实时的数据可设 `revalidate`，让页面按周期更新；强实时数据用 `no-store`。核心是分级缓存，不是一刀切关闭缓存。
3. 漏洞卡点：所有接口都 `no-store`，导致服务端压力和响应时间变差。
4. 压缩总结：缓存是默认武器，实时性需求才关闭。

## Q5：Next.js 项目里 SEO 重点讲哪些？
**A（费曼四段）**
1. 学习理解：SEO 核心是可抓取内容、语义化结构、正确元信息和稳定链接策略。
2. 大白讲解：Next 能先返回完整 HTML，对搜索引擎友好。你要讲清楚 title、description、OG 标签、结构化数据、sitemap、robots 的落地。
3. 漏洞卡点：只说“SSR 对 SEO 好”，没给可执行项。
4. 压缩总结：SEO 要靠渲染策略 + 元信息 + 抓取治理共同完成。

## Q6：中间件（middleware）常见场景是什么？
**A（费曼四段）**
1. 学习理解：middleware 在请求进入路由前执行，适合鉴权、重写、A/B 分流、地区重定向。
2. 大白讲解：它像“门卫层”，先判断请求要不要放行、跳转或改写路径，能把通用逻辑从业务页面里抽出来。
3. 漏洞卡点：在 middleware 做重计算和重 IO，导致全站请求变慢。
4. 压缩总结：中间件做轻逻辑拦截，不做重业务处理。

## Q7：水合（Hydration）报错通常怎么排查？
**A（费曼四段）**
1. 学习理解：水合报错本质是服务端 HTML 与客户端首渲染结果不一致。
2. 大白讲解：常见原因是服务端和客户端读取了不同数据、用了随机值或时间戳、或者直接在服务端渲染阶段访问浏览器 API。
3. 漏洞卡点：只会刷新页面，不会定位“哪段输出不一致”。
4. 压缩总结：保证首屏输出确定性，是避免水合问题的核心。

## Q8：Next 性能优化面试如何组织回答？
**A（费曼四段）**
1. 学习理解：Next 优化要覆盖“服务端耗时 + 前端包体 + 缓存命中 + Core Web Vitals”。
2. 大白讲解：先讲监控基线，再讲动作：图片优化、路由拆分、Server Component 下沉、缓存分层、CDN。最后给 LCP/TTFB/错误率前后数据。
3. 漏洞卡点：只有动作清单，没有量化结果。
4. 压缩总结：先量化，再优化，再复盘数据闭环。
