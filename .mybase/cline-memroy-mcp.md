## 🤔 Cline 的上下文压缩机制

### Cline 确实有自动压缩
Cline 在对话过程中会自动压缩上下文，主要通过：
1. **滑动窗口**：只保留最近的对话
2. **摘要机制**：把旧对话压缩成摘要
3. **工具结果过滤**：大文件内容不会全部保留

### 但问题在于...

**场景 1：Cline 卡死/崩溃**
- 当前对话直接丢失，压缩后的上下文也没了
- 新对话需要从头开始，无法继续之前的工作

**场景 2：上下文爆炸**
- 即使有压缩，复杂任务还是会超限
- 需要手动开新对话，但之前的上下文怎么办？

**场景 3：跨对话恢复**
- 今天做到一半，明天想继续
- 或者想回顾之前某个 task 的思路

## 💡 我们的 MCP 要解决什么？

不是"压缩"，而是"恢复"和"延续"：

### 核心功能
1. **读取历史对话**：从本地文件读取完整对话历史
2. **智能提取**：提取关键信息（不是全部内容）
   - 任务目标
   - 关键决策
   - 当前进度
   - 遇到的问题
3. **喂给新对话**：让新对话知道"之前发生了什么"

### 实际使用场景
```
旧对话卡死 → 开新对话 → 调用 MCP 读取旧对话摘要 → 告诉 AI："继续完成 xxx"
```

## 🎯 调整后的方案

### 简化版（先做最核心的）
1. **list_cline_tasks** - 列出所有任务
2. **read_task_context** - 读取任务的关键信息：
   - 首条消息（任务目标）
   - 最后 5-10 轮对话（当前状态）
   - 过滤掉大块文件内容（只保留文件名和操作类型）

### 是否需要压缩？
**需要，但不是全部压缩**：
- 原始对话可能几十万 tokens
- 我们只提取"摘要级别"的信息
- 控制在 5000-10000 tokens 以内
